# Hunger Games Agent

A web app where authenticated users chat with an AI agent that answers questions about
**The Hunger Games** saga. The agent is built with **LangChain + LangGraph** on a **RAG**
architecture: every answer is grounded in fragments retrieved from a **pgvector** database,
generated by a **local LLM (Ollama)**, and shown with its sources. When the knowledge base does
not contain the answer, the agent says so instead of inventing one.

```
 React (Vercel) ──► FastAPI (JWT) ──► LangGraph agent ──► Ollama (qwen2.5:3b)
       │                  │                  │
       └──► Keycloak ◄────┘                  └──► PostgreSQL + pgvector (e5-small embeddings)
```

| Layer | Technology |
|---|---|
| Frontend | React 18 + Vite + TypeScript, `keycloak-js` (OIDC + PKCE) |
| Backend | FastAPI, SQLAlchemy 2, Pydantic |
| Auth | Keycloak 26 (registration, login, sessions, roles) |
| Agent | LangGraph state graph + LangChain core / Ollama integration |
| LLM | `qwen2.5:3b` running locally in Ollama |
| Embeddings | `intfloat/multilingual-e5-small` (Sentence Transformers, CPU) |
| Vector DB | PostgreSQL 16 + pgvector (HNSW index, cosine distance) |
| Deploy | Frontend on Vercel, backend stack on AWS EC2 with Docker Compose + Caddy (HTTPS) |

## Run it locally

Requirements: Docker Desktop (give it at least 8 GB of RAM), Node 20+ and [uv](https://docs.astral.sh/uv/) (Python dependencies are managed with `backend/pyproject.toml` + `uv.lock`).

```bash
# 1. Configuration
cp .env.example .env
cd backend && uv lock && cd ..         # only the first time / after changing dependencies

# 2. Start Postgres, Keycloak, Ollama and the API (first build takes a few minutes)
docker compose up -d --build
docker compose logs -f ollama-pull      # wait until the model download finishes

# 3. Build the knowledge base (run on your machine, it needs internet)
cd backend
uv run scripts/scrape_wiki.py --out ../data/wiki
cd ..

# 4. Load it into pgvector
docker compose exec backend python -m scripts.seed /data

# 5. Frontend
cd frontend
npm install
npm run dev                             # http://localhost:5173
```

Log in with the demo user **demo / demo12345**, or click *Create account*.
The admin user **hga-admin / admin12345** (asked to change the password on first login) can delete any document.
Keycloak admin console: http://localhost:8080 (admin / admin). API docs: http://localhost:8000/docs.

### Evaluate the agent

```bash
docker compose exec backend python -m scripts.evaluate               # uses SIMILARITY_THRESHOLD
docker compose exec backend python -m scripts.evaluate --threshold 0.82
```

It runs the 30 questions in `backend/eval/questions.json` (20 answerable, 10 that must be
rejected) and writes `backend/eval/results.md`, ready to paste into the report.

### Tests

```bash
cd backend
# needs a Postgres with pgvector, e.g.: docker compose up -d db
docker compose exec db psql -U hga -c "CREATE DATABASE hga_test"
uv run pytest
```

Adding a dependency: `uv add <package>` (updates `pyproject.toml` and `uv.lock`), then
`docker compose build backend`.

## API

All endpoints except `/health` require `Authorization: Bearer <Keycloak access token>`.

| Method | Path | Description |
|---|---|---|
| GET | `/api/auth/me` | Current user (validates the token) |
| POST | `/api/chat` | `{question, conversation_id?}` → answer, status, sources |
| GET | `/api/conversations` | User's conversation history |
| GET | `/api/conversations/{id}` | Messages of one conversation |
| DELETE | `/api/conversations/{id}` | Delete a conversation |
| POST | `/api/documents` | Upload a file (PDF, TXT, MD, CSV, DOCX) — processed in background |
| GET | `/api/documents` | List documents in the knowledge base |
| GET | `/api/documents/{id}` | Document status (`processing` / `ready` / `failed`) |
| DELETE | `/api/documents/{id}` | Delete a document and its embeddings (owner or admin) |

## The agent

```
START → validate_intent ─greeting→ greet ──────────────┐
             │         └─unclear──→ ask_clarification ─┤
             ▼ question                                 │
          retrieve ─(nothing above threshold)→ reject ──┤
             ▼                                          │
       grade_context ─(insufficient)→ reject            │
             ▼                                          │
          generate ─(model answers NO_ANSWER)→ reject   │
             ▼                                          ▼
                                                  save_history → END
```

Hallucination controls (the assignment asks for at least two; this implements six):

1. **Similarity threshold** — chunks below `SIMILARITY_THRESHOLD` (cosine) are discarded in `retrieve`.
2. **Context validation node** — `grade_context` asks the LLM whether the fragments actually contain the answer.
3. **Strict prompt** — `generate` may only use the numbered fragments and must reply `NO_ANSWER` otherwise.
4. **Dedicated LangGraph routing** — any failed check goes to the `reject` node.
5. **Explicit rejection message** — *"I don't have enough information in my knowledge base to answer that question."* plus a suggestion to upload documents.
6. **Sources** — every answer returns the cited fragments (title, page/section, similarity, link).
